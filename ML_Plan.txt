  1. Best Insertion Point

  Compute ml_anomaly_score as a parallel signal alongside the existing anomaly_score, not a replacement.

  The insertion point is in simulation/timeline.py Phase 1, immediately after the existing anomaly_breakdown() and
  anomaly_score() calls (currently around line 220). The new score is computed from the entity's recent timeline
  window and stored on the record dict as a new field:

  # Existing (unchanged):
  breakdown = anomaly_breakdown(vessel)
  score = anomaly_score(vessel)

  # New (added):
  ml_score = ml_anomaly_scorer.score(entity_features)

  The ml_anomaly_score then flows through the pipeline identically to how prediction fields flow today — stored on
  the record, available to fusion, visible in the UI, but not wired into the critical path until validated:

  record["ml_anomaly_score"] = ml_score        # [0, 1], stored on record
  record["anomaly_score"]    = score            # unchanged heuristic score

  Phase 2 integration (after validation): add ml_anomaly_score as a fourth input to _compute_fused_score() in
  fusion.py, alongside the existing anomaly, compound, and custody terms. This is a single-line weight change to an
  existing function — minimal architectural disruption.

  The key principle: the heuristic anomaly score continues to drive all decisions until the ML score is validated.
  The ML score rides alongside as an observable signal. Swapping it in is a config change, not an architecture
  change.

  Isolation Forest, trained offline on background vessel behavior, scoring online during simulation.

  Why not deep learning

  The dataset is small (72 timesteps × 30 entities = ~2200 samples), features are low-dimensional (~15), and the
  anomaly signal is sparse. An autoencoder or transformer would be severely overparameterized for this data size and
   would not produce a meaningfully different result from Isolation Forest. Deep learning becomes justified only if
  we add real AIS data with millions of observations — which is a future phase.

  4. Training / Inference Design

  Training (offline, before simulation)

  1. Run simulation with MULTI_DAY_SCENARIO
  2. Extract records for background vessels only (is_scripted=False)
  3. Compute feature vectors from record fields + temporal windows
  4. Fit IsolationForest on the background vessel feature matrix
  5. Serialize model to disk (joblib or pickle)

  Training is a standalone script (scripts/train_anomaly_model.py) that imports from the engine and the feature
  extractor but does not modify any engine code. It produces a model artifact stored at a known path
  (models/isolation_forest.joblib).

  Inference (online, during simulation)

  1. At each timestep, after anomaly_breakdown() computes heuristic detectors:
  2. Build feature vector from current record + recent history window
  3. Call model.decision_function(features) → raw anomaly score
  4. Normalize to [0, 1] via sigmoid or min-max from training distribution
  5. Store as record["ml_anomaly_score"]

  The scorer is a thin wrapper class (MLAnomalyScorer) that loads the model artifact once and exposes a
  score(features: dict) -> float method. The simulation loop calls this wrapper; it never touches sklearn directly.

  Artifact location

  custody/
    ml/
      __init__.py
      features.py          # Feature extraction from records + history
      scorer.py            # MLAnomalyScorer wrapper (load + score)
      train.py             # Training script (standalone, not imported by engine)
    models/
      isolation_forest.joblib   # Serialized model artifact

  Decoupling

  - train.py imports from custody.simulation and custody.ml.features but is never imported by the engine
  - scorer.py imports only sklearn and custody.ml.features
  - features.py imports only from custody.features.* (existing pure feature modules) and numpy
  - timeline.py imports only scorer.py — a single new import line

  If the model artifact is missing, the scorer returns None and the record field is omitted. The system degrades
  gracefully to heuristic-only mode.

  5. Integration Plan

  Phase A: Parallel signal (no fusion change)

  The ML score exists alongside the heuristic score but does not affect decisions:

  # Record fields:
  "anomaly_score":     1.8     # heuristic (unchanged, drives decisions)
  "ml_anomaly_score":  0.72    # ML (new, observable only)

  Fusion, decision, and portfolio continue to read anomaly_score. The ML score is visible in the UI entity detail
  panel and decision trace table for comparison.

  Phase B: Blended fusion (config-driven)

  Add ml_anomaly_score to the fused_score computation in fusion.py:

  # Current:
  fused_score = 0.45 * anomaly + 0.35 * compound + 0.20 * (1 - custody)

  # New (config-driven weights):
  fused_score = (W_HEURISTIC * anomaly_norm
               + W_ML * ml_anomaly
               + W_COMPOUND * compound
               + W_CUSTODY * (1 - custody))

  The weights are defined in config.py so switching from heuristic-only to blended is a config change:

  # config.py
  FUSION_W_HEURISTIC = 0.30
  FUSION_W_ML        = 0.15
  FUSION_W_COMPOUND  = 0.35
  FUSION_W_CUSTODY   = 0.20

  Setting FUSION_W_ML = 0.0 recovers the current behavior exactly.

  Explainability

  The ML score on its own is not explainable. To preserve the system's reasoning-chain character:

  1. Feature contribution decomposition: Compute per-feature anomaly contribution from the Isolation Forest's path
  length breakdown. Store as ml_anomaly_breakdown: dict[str, float] on the record — analogous to the existing
  anomaly_breakdown dict.
  2. Top-driver labeling: The 2–3 features with the highest anomaly contribution become a human-readable string: "ML
   anomaly driven by: heading_std (0.31), zone_score_trend (0.24)". This is stored as ml_anomaly_reason on the
  record and displayed in the entity detail panel.
  3. Agreement signal: Compare ml_anomaly_score > 0.5 with anomaly_score > ANOMALY_THRESHOLD. When they agree,
  source_agreement in fusion rises. When they disagree, uncertainty rises. This is a natural extension of the
  existing _compute_source_agreement() function.
